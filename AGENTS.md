# AGENTS.md – working on lm-garmin

Guide for coding agents (Codex, Claude Code) and new contributors. Read this first, then
[docs/PLAN.md](docs/PLAN.md).

## What this is

A Python CLI that turns Lantmäteriet's **Topografi 50** (GeoPackage, CC0) into Garmin `.img`
maps for a **Garmin Montana 700**: a base map (`lm-topo50.img`) styled like Karta 1:50 000,
plus a transparent **snowmobile overlay** (`lm-skoter.img`).

Pipeline: `unpack` (zip → GeoPackage cache) → `convert` (GeoPackage → OSM PBF with `lm:*`
tags) → splitter → mkgmap (style + TYP generated from `styles/*/mapping.csv`) → `verify`
(decode the built `.img` with `java/ImgDump.java`).

## Commands

```bash
uv sync && uv run lm-garmin tools fetch          # deps + pinned mkgmap r4924 / splitter r654
uv run ruff check . && uv run ruff format --check .
uv run pytest -q                                  # unit tests (~2 s)
uv run pytest -q -m integration                   # builds the 3 fixtures to .img (~15 s, needs Java)
uv run lm-garmin style generate                   # after editing styles/*/mapping.csv – commit the output
uv run lm-garmin build --area taby --area hemavan --dev --out dist/dev   # ~10 s dev map
uv run lm-garmin build --region sweden --out dist/sweden                 # ~17 min, 2 GB
uv run lm-garmin verify dist/dev/lm-dev-topo50.img
uv run lm-garmin install dist/dev/*.img           # to a connected device at /Volumes/GARMIN
```

Java: `$LM_GARMIN_JAVA`, `$JAVA_HOME`, Homebrew `openjdk` or `java` on PATH (17+).
Data cache: `$LM_GARMIN_CACHE` or `~/.cache/lm-garmin` (unpacked GeoPackages in `gpkg/`).

## Rules

- **No map data in the repo**, releases or CI artifacts. The only exception is `tests/data/`
  (four clipped fixtures, one with the 2027.05 structure, + two raster cut-outs, made by
  `scripts/make_fixtures.py`).
- **Never commit the Skoterleder.org GPX** (OSM-derived, ODbL); use it only locally.
- Code, docs and issues in **English**; the README has a Swedish summary.
- Styles: edit only `mapping.csv`, then run `lm-garmin style generate`; the generated files
  carry a header and a test fails if they are stale. Every Lantmäteriet object type needs a
  row (or a `drop` row with a reason) – a test enforces it.
- Garmin ids: base 5750, overlay 5751, dev builds 5752/5753 (`products.py`). Every map file
  must have its own tile-number range, or the device silently skips it.
- Keep `THEME_LAYERS` order in `convert.py` fixed (it defines OSM id ranges); bump
  `SCHEMA_VERSION` in `tags.py` when tag meaning changes (`docs/tag-schema.md`).
- Commit messages end with a `Co-Authored-By:` line for the agent; PRs go to `main`.

## Device lessons (Montana 700) – see docs/device-testing.md

- Unicode maps work (Sami á ŋ č Č đ ŧ display correctly).
- Labels are drawn only for city types (`0x0100`–`0x1100`) and label points (`0x28xx`),
  **not** for `0x65xx`/`0x66xx` POIs → map texts are `0x2800`/city points.
- Roads must use standard road types (`0x01`–`0x13`); extended line types were not visible.
- Contour labels are read as **feet** by the device → label `${ele|conv:m=>ft}`.
- TYP line widths are fixed pixels, independent of zoom.
- Street names can be switched off per activity profile: *Map Setup › Advanced Setup ›
  Zoom Levels › Street Label = Off* hides them while place names and road-number shields stay
  (2026-11-22, #81). Text sizes in that menu do not change our labels.
- *Map Points* (zoom Off) hides POI symbols only; *Land Cover* hides land polygons (zoom Off)
  or their labels and **contour labels** (text None). City points and `0x28xx` label points
  follow neither (label-category kit, 2026-11-23, #81).
- Activity profiles are `Garmin/Profiles/<name>.gpf` (XML). Edits from the computer apply
  only to profiles that are **not active**: the device writes the active profile from memory
  over its file on USB connect and on profile switch; a new `.gpf` appears as a new profile
  (2026-11-23, #81).
- TYP `FontStyle` works on **lines only** (SmallFont is clearly smaller); point labels ignore
  TYP font size and colour, city types `0x0e00`–`0x1100` get no label, and label colour on
  lines had no visible effect (label kit, 2026-11-22).
- Terrain shading (#90): only via *Map Sets › Shaded Relief* (profile `ShadedReliefEnabled`
  0/2), day colours only, from any loaded map with a DEM. mkgmap needs one `--dem-dists`
  value per level or the device ignores the DEM; shading stops below the 120 m scale.
- Street search (#72): a street resolves only when its road has `mkgmap:city` set **in the
  style** (input tags are ignored with our style); the device asks for a house number first
  and falls back to the street when the map has none (2026-11-25).
- Night mode uses the TYP night colours (generated by `stylegen.night`, #92); without them
  day and night looked the same. Labels are drawn white at night by the device.
- Extended types: subtype ≤ `0x1f` (mkgmap rejects more); a fully transparent TYP line is
  rejected (use pattern `label`).

## Release status

**v0.4.0** (2026-11-26): "Terrain" – terrain shading from Markhöjdmodell grid 50+ (#90,
`--dem-dir`), TYP night colours (#92) and street search by street name (#72: NVDB
municipality as city, named roads in NET, `--index --net`). Sweden 2.29 GB in 23 min.
Accepted on the Montana 700. Grid 50+ exists only as *hdb* on Geotorget.

**v0.3.0** (2026-11-23): "Street names" – NVDB street names in the release map (small
line font), lake and mountain labels restored (#79), county/municipality maps cut at the
border, Topografi 50 2027.05 structure supported side by side (ADR-0008, CI fixture), and
the device-side settings mapped (street names, contour labels, POI symbols, land cover per
activity profile; profiles writable from the computer when not active). Accepted on the
Montana 700.

**v0.2.0** (2026-11-21, see [CHANGELOG.md](CHANGELOG.md)): "Everyday map" – labels thinned
by text size class and harder in towns, searchable lakes and terrain names, optional NVDB
street names (`--nvdb-dir`, [street-names.md](docs/street-names.md)), road shields, calmer
street network and hatching, overlay readable outdoors. All accepted on the Montana 700
([device record](docs/device-testing.md)). v0.1.0 (2026-11-20) was the first release.

Device lessons added in v0.2: the device's zoom ↔ level mapping (2 km ≈ resolution 20,
1.2 km ≈ 21, 650–900 m ≈ 22, ≤ 400 m ≈ 23–24); labels are cut after about 24 characters;
geographic POIs (0x65xx/0x66xx) are searchable but unlabelled, label points (0x28xx) are
labelled but not searchable; TYP line bitmaps have two colours; `name` never replaces a
label already set (use `relabel`). *Where to?* lists *Addresses* only when a loaded map has street data (mkgmap `--net`/`--route`).

Next: [v0.5 "Navigation"](https://github.com/nilande/lm-garmin/milestone/10): routing (#28,
including merging road pieces so the line budgets hold), house numbers for address search,
legend colours (#68); the #81 ADR on device-side configuration
(#77, #78, #80). [Topografi 50 2027.05](https://github.com/nilande/lm-garmin/milestone/11):
the real-data check when Lantmäteriet delivers (#56). M5 Later: packaging (#30), the
single-file bundle (#51), cp1252 (#17), CI performance trends (#26), the style-only rebuild
target (#27). Test iterations on single municipalities (Täby, Storuman) with
`--municipality … --dev`; one Sweden build is the final check before a release.
